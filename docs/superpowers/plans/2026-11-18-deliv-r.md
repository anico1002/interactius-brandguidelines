# Deliv_r — plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Herramienta Deliv_r en el Workspace de brand para que el equipo publique entregables confidenciales (HTML/PDF/ZIP exportados de claude.ai) en `/clientes/<cliente>/<id>`, con acceso por persona y artefacto.

**Architecture:** Lógica pura en `lib/deliv/` (portada de `lib/clientes/` de la web, probada con `node --test`) sobre una interfaz `RepoDeliv`, con una implementación en memoria para tests y otra Supabase. Las rutas del equipo usan `supabaseAuthServer()` con RLS `authenticated` (patrón del workspace); la superficie pública y lo que toca contraseñas usan `lib/deliv/servidor.ts`, único módulo con la `service role`. Bucket privado `deliv-r`. El equipo usa su login de Google existente (`requireUser()`); los clientes, cookie firmada propia. La subida va del navegador a Storage con URLs firmadas, tras validar y optimizar imágenes en el navegador.

**Tech Stack:** Next.js 15 App Router, TypeScript (node `--experimental-strip-types`), Supabase JS 2 (`@supabase/supabase-js`), `fflate` (ya instalado), `node:crypto`, `node:test`, CSS por funcionalidad con variables `--c-*`.

**Spec:** `docs/features/deliv-r.md` (la definición: léela entera antes de cada tarea; es el contrato). Prototipo de interacción: `deliv-r-prototype.html`.

## Global Constraints

- Imports dentro de `lib/` **relativos y con extensión `.ts`** (`import { x } from './ids.ts'`); los tipos con `import type`. Nada de `enum`, `namespace` ni parameter properties (node strip-types). Componentes y rutas pueden usar `@/`.
- Tests con `node:test` + `node:assert/strict`, en `lib/deliv/__tests__/*.test.ts`; añadir ese glob al script `test` de `package.json`.
- La variable `SUPABASE_SERVICE_ROLE_KEY` y el módulo `lib/deliv/servidor.ts` solo se referencian desde: `lib/deliv/servidor.ts`, `lib/deliv/config.ts`, `app/clientes/**`, los `page.tsx` de `app/workspace/deliv_r/**` (componentes de servidor que leen usuarios y último acceso; comprueban antes la sesión de equipo), y las rutas de `app/api/deliv_r/**` que crean usuarios o tocan contraseñas (`…/accesos`, `usuarios/**`). `lib/deliv/servidor.ts` empieza por `import 'server-only'`. El resto de rutas del equipo usa `supabaseAuthServer()`.
- Secretos: `DELIV_SESSION_SECRET` (≥ 32 caracteres) y `SUPABASE_SERVICE_ROLE_KEY`, escritos literalmente como `process.env.X`. Sin ellos: fail-closed («Servicio no disponible.» / 503).
- Alfabeto de IDs y contraseñas: `abcdefghijkmnpqrstuvwxyz23456789`; id de artefacto 10 caracteres; contraseña 16 en grupos de 4 con guiones.
- scrypt N=16384, r=8, p=1, salt 16 B, clave 32 B. Cookie de cliente `__Host-deliv_clientes`, HttpOnly, Secure, SameSite=Lax, Path=/, 7 días. Bloqueo 5 fallos → 15 min. Token de archivo 15 min en la ruta.
- Slugs de cliente: `^[a-z0-9]+(-[a-z0-9]+)*$`; reservados `login`, `logout`, `admin`, `archivos`.
- Tablas `deliv_artefactos` (`id` uuid PK + `public_id` text unique + `created_at`/`updated_at` con `set_updated_at`), `deliv_usuarios`, `deliv_accesos` con RLS: `anon` nada; `authenticated` gestiona artefactos y accesos; `select (hash)` revocado a `authenticated`. Bucket `deliv-r` privado con `insert/select/delete` para `authenticated` y nada para `anon`.
- Redirecciones con `Location` relativa. `Referrer-Policy: same-origin` en `/clientes`. CSRF: `Origin` = host, o `Origin` null/ausente con `Sec-Fetch-Site: same-origin`.
- Marca (definición § Marca): valores de `lib/tokens.ts`/`lib/typeScale.ts` y `--c-*`; **CTA como enlace subrayado con `hover-wipe`** (`lib/motion.ts`), no botones con relleno; errores y avisos en **Burdeos**; sin cursiva; Plex Serif 300/400; Plex Mono 400/500/600; copy sin `!`, `¡`, `…`, `...` ni vocabulario prohibido. CSS propio en `components/deliv/deliv.css`.
- Mensajes al cliente: «Usuario o contraseña incorrectos.» · «Demasiados intentos. Prueba de nuevo en unos minutos.» · «No tienes acceso a este contenido.» · «Servicio no disponible.»
- Ningún archivo de cliente, credencial ni correo real en el repo.
- Verificación de cada tarea: `npm run type-check && npm test && npm run lint && npm run eval:content` (y `npm run build` en las tareas que tocan rutas). Nunca `pkill`/`killall`: si arrancas un proceso, para solo su PID.
